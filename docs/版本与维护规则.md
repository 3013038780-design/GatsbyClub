## 四条维护规则

1. **项目决定先更新基础文件**，再检查待办、产品卡、模型和展示是否需要同步；不为一次内部方向变化重写旧行业事实。
2. **正文、源数据、网页副本各司其职**。研究数据保留在原生成目录；网页随包的PDF/XLSX是副本，不成为第二个权威版本。
3. **历史目录保留日期和路径**。不批量移动`outputs/`里的源文件，也不因文件名带“final”就认定最新版。日常从导航指定入口进入。
4. **每次更新可追溯**。补一条更新记录、检查文档链接与附件、同步GitHub分支及PR；原始会议、账号状态与未公开股权资料留本机私有区。

## 目录职责

```text
README.md                 人阅读的总入口
AGENTS.md                 协作与首读约定
docs/                     项目共识、全资料导航、维护规则
  history/                旧首页与旧待办，仅供追溯
assets/                   README的本地图片
outputs/                  按日期形成的研究、成品、网页及原始证据
scripts/                  本次导航与文档检查工具
tools/                    采集工具与来源
archive/                  同步、验收与文件哈希清单
```

`raw/collection-*/social-platforms`放采集，`qa/formatting`放检查，`site/dist`放展示和下载副本，`交付文件/deliverables`放阅读成品。旧目录维持原样，分类由[总导航](项目文件导航.md)和各目录README明确。

早期`private-club-site/`和`club_research_20261019/`为历史来源，保留原路径方便复核；不作为当前项目定位与会籍权益的定义。
